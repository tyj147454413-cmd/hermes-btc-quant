# Hermes BTC 自我学习系统状态快照

> 这是 2026-08-21 round35 + round35.1 完成时点的"项目状态全景图"。任何接手者读这一份就能掌握全貌。

## 一、架构共识(三层学习 + 监控环并列)

### 三层学习模型(数据量匹配机制)

| 层 | 内容 | 学习方式 | 数据门槛 |
|---|---|---|---|
| 统计层 | 四维胜率表(`rule_engine._probability`) | **自动**(查表映射) | 211 场已够,n≥30 单格可落表 |
| 权重层 | 评分表 ×1/×2 因子权重 | **半自动**(30+样本+反事实) | 约 2.5 个月后 1000 场达 |
| 结构层 | G1-G6/H 规则/翻向逻辑 | **仅人工**(回测+拍板) | 1000+ 场 + walk-forward |

**Why**: round18/20/22/23/25/31.1 反复证明——机器搜规则胜率偏反(momentum_health 46.7%)。

**How**: 改规则前归类到三层。统计层可直落,权重层必反事实,结构层必拍板。

### 监控环 vs 学习环(并列不混合)

- **学习环**: 统计/权重/结构三层,产出"候选规则"→ 反事实 → 拍板 → 落表
- **监控环**: 时序/流程/审计指标(last-check 触发率、refresh 率、引擎校验一致性)
- **不混合**: 学习环参数是"学出来的",监控环参数是"可监控的"(无学习目标)

**Why**: round33.2 last-check + round35.1 refresh 案例证明,流程类问题不能当学习参数。

**How**: 写提案先问"这是参数还是流程?"——参数进学习环,流程进监控环。

### 五护栏(任何落表必守)

1. **学习率**: 每轮最多改 2-3 格 / 1 权重
2. **n<30 永不落**: 全表 17 格目前全部 n<30,仅告警不动表
3. **人工批准**: 落地前必须,先例 round24 用户亲自回退 0.60 封顶
4. **30 场监控窗**: 胜率恶化超阈值自动回滚(round35 监控窗已启动)
5. **概率表折扣 ≠ 风控**: EV 不 SKIP / 0.60 封顶不读 confidence / 金额缩仓已废除(8/12)

### 候选规则 schema(进队列前必填)

```
{
  "条件": "字符串化触发条件",
  "动作": "提议的规则改动",
  "来源场次": ["slug 列表"],
  "行为改变数": 0,                    # 必须 ≥1
  "净效果": 0,                        # 翻对-翻错,必须 >0
  "verification_status": "unverified" | "self-verified" | "engine-verified",
  "状态": "proposed" | "backtested" | "approved" | "rejected" | "landed"
}
```

**Why**: round35 前的"教训躺 markdown"问题 + 我之前提"命中数≥1"门槛挡不住无效教训的反例(教训1 命中数=1 但行为改变=0)。

## 四、方法论沉淀

### 教训元教训

任何"基于 N=1 样本想改规则"的 push back 都应触发:

1. **Wilson 下界 + 反事实验证** (本场反例: G5 翻向全库命中仅 1 场且引擎本来就对)
2. **真实因果链 vs 假想因果链区分** (本场反例: 5pm-et LOSS 真因是流程不是规则)
3. **假因果链 → 假教训 → 假规则 → 系统越改越烂**

### 自我学习系统的反定义

> **自我学习系统 ≠ 自动改规则**。
> **自我学习系统 = 自动阻止错误改规则 + 自动产生可追溯决策文档**。

5pm-et 这轮核心价值:

- ✅ 拒绝修(基于错误前提的 5 条教训没进规则)
- ❌ 没修(真问题留给监控环)
- ✅ 阻止重犯(案例研究 + 笔记补遗 + 元教训三件套)
