# Hermes BTC → 顶级专业量化模型 路线图

> 生成日期：2026-09-05 | 配套：`MODEL_SYSTEM_MANUAL.md`（当前系统说明书）

---

## 零、先说大实话：当前位置的诚实定位

顶级专业量化 = **alpha 发现 × 方法学严谨 × 工程可靠性** 三根支柱。当前状态：

| 支柱 | 现状 | 距离顶级的差距 |
|---|---|---|
| **Alpha 发现** | 剔除动量后 AUC=0.541 ≈ 随机。**尚未找到市场未定价的独立 alpha** | 最大差距，没有之一 |
| **方法学** | walk-forward 已有、消融/A/B 已有；但无净化/禁运、无多重检验控制、无统计显著性检验 | 中等——框架对，武器库不全 |
| **工程可靠性** | 训练推理同源代码（好）、影子模式（好）、幂等写入（好）；但无漂移监控、无实验追踪、无回滚自动化 | 中等——单机作坊级，非机构级 |

**核心认知**：机构级团队的优势不是模型算法（LightGBM 谁都能跑），而是：
1. 数据优势（别人拿不到/拿得慢的数据）
2. 验证纪律（不骗自己）
3. 执行优势（成本低于对手）

下面按「优先级 × 层级」给出完整路线图。**P0 最高**。

## 一、P0：Alpha 验证与止血（本周～2 周内，已部分上线）

这是所有后续工作的前提。在证明有真 alpha 之前，任何模型升级都是给地基不稳的楼加装修。

### P0.1 双周裁决机制（已上线 ✅）
gs vs gs_nomtm 影子 A/B 已于 2026-09-05 部署，每月 1/15 号自动裁决。

### P0.2 把「EV 结算」立为唯一 KPI
- AUC/ACC 只能当过程指标；`ev_settlement.pnl_ev_only_usd`（仅正 EV 出手的 paper PnL）是唯一裁决标准
- **行动**：给 ev_watch / cv_report 增加滚动 7 天/30 天 EV 曲线，而不只是累计值
- **验收**：能一眼看出「模型方向 × PM 价」的滚动盈亏趋势，而非单点数字

### P0.3 假设驱动的 alpha 候选清单（研究，零成本）
列出所有「PM 市场可能没及时定价」的候选信号，逐个检验（每个都要写预期效果再验证，防数据窥探）：

| 候选 alpha | 假设 | 检验方法 |
|---|---|---|
| Binance→PM 传导延迟 | 币价先动，PM 做市商报价更新有 1-5 秒延迟 | 用 book_snapshots 的秒级时间戳测 PM 价对 Binance 价格的响应滞后 |
| 最后一分钟动量 | :55 决策点离结算 5 分钟，短动量的信息含量最高（做市商来不及完全消化） | dm50/dm55 影子数据单独评估 EV（已积累） |
| 尾部盘感 | pm_delta 大幅压价/拉升后的均值回归（零售过度反应） | |pm_delta|>0.15 分组的结算胜率 vs pm_up_dec |
| 订单簿失衡 | Binance bid/ask 失衡预测下一分钟方向 | MicroSnap 数据（5 分钟粒度偏粗，见 P1.2 升级） |
| 清算级联 | 大额清算后的延续/反转 | Binance forceOrder 流（目前未采集，见 P1.3） |
| 时段季节性 | 美盘开盘/伦敦收盘等特定 ET 小时的定价偏差 | hist_up_rate 已是雏形，扩展为分时段 EV 分析 |

**验收**：每个候选给出「样本内信号强度 + 影子样本外 EV」二联结论，淘汰或晋级。

## 二、P1：数据层升级（1～2 个月，alpha 的原料）

顶级机构的第一优势永远是数据。原则：**采集一切未来可能有用、且现在不采以后就永远没有的数据**（快照类不可回溯）。

### P1.1 历史深度：60 天 → 18 个月
- `backfill_data.py --start 2024-03-01` 一次回补（K 线缓存机制已支持，成本≈半天）
- 12 个 dm 各拿到 ~1.3 万样本，v1 回归 walk-forward 才有统计意义（现在 60 天只有 4-5 个测试月）
- **验收**：每 dm ≥10,000 行，wf 测试窗 ≥12 个月

### P1.2 订单簿采集升级（当前最大数据机会）
现状：`binance_ob_snapshot.py` 每 5 分钟一次、仅 top 档。升级路线：

| 升级项 | 做法 | 为什么 |
|---|---|---|
| 频率 5min → 10s | 决策点前后（:50-:60）尤其密集 | 5 分钟粒度测不了微观结构 |
| 深度 top1 → 全深度 | depth20 快照存 parquet 按天分区 | 订单簿压力/斜率需要多档 |
| 增加逐笔成交流 | `aggTrades` 增量拉取 + aggressor 标记 | CVD/OFI 的原料 |
| Binance + PM CLOB 双边 | PM 订单簿也快照（book_snapshot.py 已有雏形） | 直接测「模型 fair 价 vs PM 订单簿」的错价 |

- **存储设计**：按天分区 parquet + 压缩；一天 10s 级快照 ~8,640 条 × 双边，单日 <100MB
- **验收**：连续 7 天无缺口；能重建任意决策点前 5 分钟的完整订单簿状态

### P1.3 新增数据源（按性价比排序）

| 数据 | 来源 | 预期用途 | 成本 |
|---|---|---|---|
| 强平流水 | Binance Futures `forceOrder` | 波动放大器，尾部信号 | 低（WebSocket/轮询） |
| OI 持仓量 | `openInterestHist`（仅 30 天，必须持续采集！） | 拥挤度/变盘前兆 | 低，但**不可回溯，现在就要开始存** |
| 期现基差 | 永续 vs 现货价差 | 资金费率的高频前导 | 低 |
| Deribit 期权 | IV / 25d skew / RR | 尾部风险定价，专业信号源 | 中（API 免费档够用） |
| 多所价格分歧 | OKX/Coinbase vs Binance | 跨所 lead-lag | 中 |
| 宏观日历 | CPI/FOMC 时间表 | 高波动时段过滤/加权 | 低 |
| 链上稳定币流量 | Glassnode 免费档 | 中期情绪 | 中 |

### P1.4 数据质量管道（作坊→机构的分水岭）
- 自动完整性检查：每小时校验 12 决策点记录齐全、K 线无缺口、快照连续
- 异常检测：锚定价跳变、PM 价越界（>1 或 <0）、概率 NaN——发现即告警
- 数据血缘：dataset 生成参数 + 原始文件 hash 写进 manifest（复现保障）
- **验收**：`data_quality_check.py` 每日跑一次，输出缺失/异常清单

## 三、P2：标签与目标函数升级（与 P1 并行，纯代码）

### P2.1 二值方向 → 三重障碍标签（triple-barrier）
现状 `label = close > open` 与实际交易不完全对齐。升级为：
- 上障碍（止盈线）、下障碍（止损线）、时间障碍（H+1:00），先触碰哪个定标签
- 障碍线按近期已实现波动率缩放（波动大→线放宽）
- **为什么重要**：模型直接学「这单值不值得下」，而非「方向是什么」
- **验收**：新旧标签的混淆矩阵对比 + 新标签下 AUC 变化

### P2.2 Meta-labeling（最贴合现状的升级）
López de Prado 框架：不再预测方向，而是**给引擎已有信号打分**（要不要跟、下多大注）。
- 一级 = 现有引擎方向；二级 = 模型输出「该信号胜率」
- 优势：绕开「模型方向精度必须 > 市场定价」的死结，直接优化仓位效率
- **验收**：按二级模型分层后的引擎信号 EV 对比（高分组 vs 低分组）

### P2.3 样本加权
- 按波动率/流动性加权（死区只是粗暴版）
- 影子期样本 ×3 权重（分布与实盘最近）

## 四、P3：特征层升级（数据到位后）

### P4.1 特征筛选体系（目前只有缺失率过滤）
流水线化四步：
1. **单变量筛查**：IV（信息价值）、互信息、单特征 AUC
2. **稳定性**：PSI（训练窗 vs 最近 2 周分布漂移）>0.25 剔除
3. **冗余聚类**：相关系数 >0.9 的簇只留 IV 最高者
4. **增量价值**：SHAP/MDI 淘汰末位（一次只动一个）
- **验收**：`feature_screening.py` 一键出报告，特征表版本化管理

### P3.2 微观结构特征（等 P1.2 数据）
- OFI（订单流失衡）、多档订单簿压力比、microprice 偏离
- VPIN（毒性流）、大单占比（已有 DUMP_TRAP 雏形可深化）
- 已实现波动率族：Parkinson / Garman-Klass / 已实现核（比 5m std 高效）

### P3.3 Regime 特征
- 波动率 regime（GARCH 或分位数分类）
- 趋势/震荡分类器输出作为特征
- 拥挤度：OI 变化 × 资金费率同向程度

### P3.4 跨资产特征
- ETH/BTC 相对强弱、ES 期货隔夜方向、DXY 当日方向（加密与传统市场相关性按时段变化）

## 五、P4：模型层升级（P3 之后，且必须等 alpha 验证通过）

> 顺序纪律：**先证明有信号，再堆模型**。没有 alpha 时换更强模型 = 更精致地拟合噪声。

### P4.1 超参优化
- Optuna 50-100 trial，**目标函数必须是 walk-forward 平均 OOS 指标**（不是验证集单点）
- 搜索空间：树深/叶数/lr/正则/特征采样
- **验收**：OOS 提升 >2 个点才采纳，否则维持简单参数

### P4.2 集成体系
- LGBM + XGBoost + CatBoost + 弹性网络，时序感知 stacking（blender 也用 walk-forward 训练）
- CatBoost 的 ordered boosting 天然抗目标泄漏，值得一席
- **验收**：集成 OOS ≥ 最佳单模型 + 稳健性（多种子方差更小）

### P4.3 不确定性量化（顶级团队的标配）
- Venn-ABERS / conformal prediction：输出概率区间而非点估计
- 用途：EV 计算用概率下界（保守出手），样本不足时自动收手
- **验收**：校准覆盖率达到名义水平（说 90% 区间就真有 90% 覆盖）

### P4.4 在线适应
- regime 突变（如波动率跳档）时静态模型失效
- 方案：每日增量重训 / 样本指数衰减加权 / 触发式重训
- **验收**：模拟 2024-08 类波动事件，衰减加权版回撤更小

## 六、P5：验证方法学升级（顶级与平庸的真正分水岭）

这是「不骗自己」的能力。机构与散户的最大区别不是模型，是**知道自己什么时候在自欺**。

### P6.1 净化交叉验证（CPCV）
- 现状 walk-forward 只有一条历史路径，结论方差大
- López de Prado CPCV：组合式切分生成几十条 OOS 路径 + **purging**（剔除与测试窗标签重叠的训练样本）+ **embargo**（测试窗后隔离带）
- 1h 标签在决策点后最多 1h 才结算 → 相邻样本天然重叠，**当前 walk-forward 严格说存在轻度泄漏**（同小时跨 dm 样本共享标签）
- **验收**：`cpcv.py` 报告含路径数/各路径 AUC 分布（均值±std）

### P6.2 多重假设检验控制（防「试出来的运气」）
- 已试过 N 个特征/模型/参数组合后，单次 OOS 提升的显著性要打折
- 工具：Deflated Sharpe Ratio、White Reality Check / SPA test
- **最低要求**：维护「实验登记表」——每条记录假设、改动、结果（现有 metadata 可扩展）
- **验收**：最终模型的 OOS 指标附 DSR 校正后 p 值

### P6.3 统计功效与样本量纪律
- 回答「多少影子样本才能区分 AUC 0.55 与 0.60」：双比率检验 → 每 dm 约需 600-1000 样本（约 4-6 周积累）
- **验收**：裁决报告自动标注当前样本量对应的置信区间宽度

### P6.4 稳定性测试
- 多种子（42/7/2024…）训练 → 指标方差大 = 模型不稳，弃
- 参数 ±10% 扰动 → 性能悬崖 = 过拟合信号
- **验收**：纳入训练脚本的 `--stability-check` 模式

## 七、P6：校准与 EV 层（转实盘前必须完成）

### P6.1 校准升级
- 分 regime 校准（高/低波动日各一套参数）
- Venn-ABERS 替代 Platt：小样本下给出上下界
- 常态化可靠性图 + Hosmer-Lemeshow 检验

### P6.2 EV 从「理论」到「可成交」（当前 EV 最大的坑）
现状用 Gamma mid 价计算 EV——**mid 价不是你能买到的价**。升级：
1. PM CLOB bid/ask 实抓（book_snapshot.py 已有基础）
2. 价差模型：分时段统计 PM 价差分布（开盘宽/临近结算窄？）
3. 滑点模拟：决策到成交的 pm_up 漂移（用影子数据的相邻 dm 价差实测）
4. 手续费/gas 精确计入
- **验收**：`ev_realistic = f(model_p, ask_price, slippage, fee)` 全链路可回放

### P6.3 仓位科学
- 分数 Kelly：f* = edge/odds，再打 1/4 折扣（估计误差保护）
- EV 置信区间低于 0 → 不出手（与 P4.3 不确定性量化联动）
- 连续小时相关性折算（有效样本数 < 名义样本数）

| 项 | 内容 |

## 九、P8：基础设施（规模化后）

1. **实验追踪**：MLflow（或轻量 JSON registry 扩展）——每次训练的参数/数据 hash/指标/产物自动归档
2. **漂移监控**（TRAINING_PLAN 早已规划、未实现）：滚动 200 样本 AUC + 特征 PSI + CUSUM 告警，低于阈值自动降级回引擎
3. **复现性**：requirements 锁定 + 数据 hash + 随机种子全记录（部分已有）
4. **调度健壮性**：Windows 计划任务 → NSSM 服务化（watchdog 已有，防任务静默失败）
5. **备份**：影子数据/快照数据异地备份（GitHub 私有仓或 NAS）——这些不可回溯数据是最大资产

## 十一、什么不值得做（反向清单）

| 不做 | 原因 |
|---|---|
| Transformer 大模型 | 万级样本 + 弱信号下必过拟合；TRAINING_PLAN 已正确排除 |
| RL 强化学习下单 | 状态空间大 + 数据少；执行优化用模拟器迭代足够 |
| 高频 tick 级策略 | PM 每小时结算 + CLOB 流动性有限，天花板低 |
| 更多技术指标（布林/CCI/ADX…） | 与现有 34 特征高度共线，信息增量为零 |
| 实时新闻/NLP 情绪 | 1h 窗口内新闻已被价格消化；落地复杂度不成比例 |
| AutoML 全自动搜特征 | 没有假设的搜索 = 数据窥探制造机，多重检验成本远超收益 |
